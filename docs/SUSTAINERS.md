# Sustainer 箱子装配实施前分析

分析对象：用户本地 `261021_VAULT_USSA_S` 模型包。模型库只读；原说明书和 STL 不复制到仓库。

## 已核对的装配关系

`03_Sustainers Assembly.pdf` 共 7 页、12 步：

| 步骤 | 装配关系 |
| --- | --- |
| 1–2 | 小销连接 Lock Holder 与 Lock Inner Part；大销连接 Inner 与 Outer，注意 UP 朝向。 |
| 3–4 | 锁组件固定在前面板上，使用 M4 × 14 mm。 |
| 5–6 | 上铰链固定到顶盖（M4 × 14 mm），下铰链固定到箱体（M4 × 10 mm）。 |
| 7–8 | 顶盖与箱体通过铰链配合，并插入两根轴杆。 |
| 9–10 | 前面板固定到箱体（M4 × 20 mm），再插入标签。 |
| 11–12 | 移除手工支撑，再安装所选隔板。 |

箱子不使用抽屉的 Box、Runner Guide、Runner Slide、Geared Rails、Key、Springs 或 Latch。应使用独立的 BOM 和约束图：箱体为根，前锁面板固定到箱体，锁组件从属于面板；顶盖绕后部铰链轴开合，上铰链跟随顶盖，下铰链和轴杆从属于箱体。

总说明书第 17 页标注每套 M4 × 14 mm 16 个、M4 × 10 mm 8 个、M4 × 20 mm 7 个。该图使用 L 型示例；不能据此断言所有 S/M/XL 规格都有相同的螺钉数量。五金没有对应 STL，不应伪装成已建模零件。

## 文件覆盖与匹配

箱子目录包含 **225 个 STL**：

- S/M/L：3–7 格深度，1F/2F/4F；XL：3–7 格深度，仅 1F，共 50 个尺寸组合。
- S/M 每种尺寸只有一种 Module；L/XL 提供 Flat、Dividers、Sealed 三种 Module。S/M 不应虚构三个箱体变体。
- 深度 3–5 顶盖为整体件；6–7 同时有 Whole、Part 1、Part 2 和 Connector。整盖与分体盖是互斥方案，不能同时加入打印清单。
- `Roof` 与 `Roofs` 目录混用；M Module 的扩展名前有空格；存在 `M4f`、`L4F'`、`XL3  Roof`、`XL6  Roof Whole` 等实际命名。需要在 catalog.rs 中规范化匹配，并保留实际源路径。
- 家族目录和 Universal/Facades 中存在同规格面板候选。九组 S/M/L 候选的 STL 字节与三角面数均不同，不能认定是相同网格的副本；需要比较安装孔和锁槽，再确定使用哪个版本。两组不能自动同时装上。
- `Label for Sustainers.stl` 与抽屉 `Label.stl` 不同，现有抽屉文字加工逻辑不能直接用于箱子标签。
- 箱子底板位于 Universal/Baseplates，隔板位于 Universal/Dividers；现有抽屉内部编辑器的网格、槽位和放置高度不能直接沿用。

## STL 几何核对

完整尺寸和三角面清单保存在本地 `output/sustainer-analysis/stl-inventory-fast.json`。尺寸假定 STL 单位为 mm。

| 示例 | 原始 STL 轴向包围盒（X × Y × Z）mm | 含义 |
| --- | --- | --- |
| S3 1F Module | 164.806 × 50.800 × 146.100 | 原始 Y 为层高方向，不能按 STL 的 Z 直接当高度。 |
| S1F 面板 | 164.802 × 46.000 × 10.000 | 正面板独立于箱体。 |
| S3 Roof | 130.431 × 122.301 × 156.097 | 在 XY 平面斜放，轴向宽度不代表真实盖宽。 |
| S Hinge Top | 14.000 × 57.000 × 62.800 | 一份 STL 中检测到一个连通实体。 |
| M Hinge Top | 14.000 × 57.000 × 98.800 | 一份 STL 中检测到一个连通实体。 |

S3 Roof 的主平面法线约为 `(0.679, -0.734, 0)`；沿其垂直方向测得约 164.8 mm 宽，而不是包围盒的 130.4 mm。不能套用现有 scene.rs 中固定的 `-45°` 顶盖示意旋转，其他尺寸也需要单独检查主平面。

按 0.0001 mm 顶点焊接进行连通分析：

| 源文件 | 每份 STL 的连通实体数 |
| --- | --- |
| S-M 1F Hinge / S-M 2-4F Hinge | 2 |
| L-XL 1F Hinge / L 2-4F Hinge | 2 |
| S Hinge Top / M Hinge Top | 1 |
| L-XL Hinge Top | 2 |
| S-M Rods / L-XL Rods | 2 |
| 1 SET OF PINS FOR 1 LOCK | 4 |

连通实体数量不等于最终物理零件数量：原 STL 可能带手工支撑，需要结合图示区分。特别是 S/M 上铰链，不能因 L 示例图有两个铰链就把源文件打印份数直接设为 2。展示拆分只改变显示实例，打印清单仍以源文件份数计数。

## 实施边界与顺序

1. catalog.rs 增加独立箱子选型和 BOM：实际路径解析、同规格面板单选、整盖/分盖互斥、按规格选铰链和锁外件。本次已检查全部 50 个尺寸组合，箱体、家族面板和顶盖均有实际文件，矩阵见本地 `output/sustainer-analysis/size-matrix.json`。
2. display.rs 增加经过实体数核对的只读拆分规则。手工支撑只在确认识别规则后从显示网格移除，保留源 STL 和导出打印几何。
3. scene.rs 创建箱子实例；单独的箱子装配模块从几何平面建立箱体、盖和面板基准。constraints.rs 增加绕锚点的铰链关节，固定其他组件；禁止复用抽屉滑动关节。
4. app.rs 开放箱子方案、箱体类型和整盖/分盖选择、开盖预览（可先使用 0–110° 作为展示范围，这不是已验证的机械行程）；方案和校准坐标使用独立键保存，避免覆盖同尺寸抽屉配置。
5. 先校准 S3/1F 与 L3/1F 的上下铰链、轴杆、锁和标签，再覆盖 M、2F/4F、XL 与分体盖。未核对的变换必须保持“估计 / 未校准”。
6. 复用选中、隔离、颜色、透明和爆炸预览，保持 STL 解析在后台。箱子内部布局、标签文字及分体连接件在专用配合确认后接入，不能以抽屉规则自动猜测。
7. 修改代码后运行 cargo fmt、cargo test、cargo clippy，并用原生 --smoke-test 检查闭盖、开盖、爆炸和回归抽屉场景。网格表面相交诊断只能作为辅助，不能宣称完成 CAD 或制造验证。

## 当前证据不足的项目

尚未建立并验证各规格的铰链轴坐标、锁销轴线、标签安装面、分体顶盖接缝与连接件位置；因此目前不能把基于包围盒的示意摆放称为已完成箱子装配。7 页装配图提供关系和方向，没有完整的尺寸标注。需要继续以真实 STL 的孔位、平面和圆柱轴提取基准，并通过开合过程核对。


## 首版实现状态（2026-10-31）

已接入箱子方案、独立 BOM、箱体类型、整盖/分盖选择、装配树和 0–110° 箱盖关节；上铰链及分盖跟随箱盖，其他组件固定到各自父级。打印份数与展示实体分开，打印勾选不删除完整箱子的展示件。方案保存选型与开盖角度，箱子校准键包含类型、尺寸、箱体和顶盖方式。

主平面选择结合面板实际宽度，避免 XL 斜放箱体以及高箱体侧壁被误作底面。源网格解析、装配计算及校准文件解析均在预览后台进行。原始网格、打印朝向和手工支撑保持只读。

硬件位置、标签槽、分体顶盖接缝和连接件仍为估计；前锁保留闭锁形态，不模拟解锁。内部底板、隔板布局和箱子标签文字尚未接入。全规格网格尺寸检查与开合关系检查只能确认展示数据一致，不能据此宣称配合已校准或通过 CAD/打印验证。


## 本轮验证

- `cargo fmt --check`、`cargo clippy --locked --all-targets -- -D warnings` 通过。
- `cargo test --locked`：124 个通过，1 个既有手动审计测试忽略；无模型库环境变量的外部模型测试按既有约定跳过数据读取。
